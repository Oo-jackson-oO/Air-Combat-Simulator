# 网络对战升级 Spec

## Why
当前项目仅支持单机运行，`INetworkProtocol` 仍为空实现，无法支撑多端实时对战与状态一致性。此次升级需要在保留现有分层约束的前提下，引入可验证的联网能力，并优先保证在网络波动场景下的模型一致性与可恢复性。

## What Changes
- 新增权威服务器房间架构，客户端只提交输入指令，服务端负责节拍推进、命中裁决与战局广播。
- 新增基于 WebSocket + JSON 的节拍同步协议，覆盖房间加入、准备、输入上传、状态快照、重同步与断线恢复。
- 改造模型层更新入口，将本地即时输入驱动调整为“按节拍消费输入并推进模型”的同步模式。
- 新增客户端网络会话层，用于连接管理、心跳、延迟测量、快照接收与插值显示。
- 新增网络抖动处理机制，包括输入序号、快照版本号、客户端预测纠偏与服务端全量重同步。
- 新增多端验证方案，覆盖双端联机、弱网延迟、乱序/丢包模拟下的状态一致性检查。
- 新增功能分支规范，首个实现分支命名固定为 `feature/network-battle-sync`。
- **BREAKING** `GameEngine` 的部分更新职责将从纯本地循环调整为“本地渲染循环 + 网络节拍消费”，相关控制流与快照结构会发生变化。

## Impact
- Affected specs: 分层架构、网络对战接口预留、模型层节拍同步、战斗判定与状态展示
- Affected code: `src/game/interfaces.ts`、`src/game/controller.ts`、`src/game/model.ts`、`src/components/AirCombatPlatform.tsx`、新增网络服务端与客户端会话模块

## ADDED Requirements
### Requirement: 权威服务器房间对战
系统 SHALL 提供一个权威服务器房间，负责接收客户端输入、按固定节拍推进战场模型，并向所有客户端广播统一战局状态。

#### Scenario: 双端进入同一房间
- **WHEN** 两个客户端连接到同一房间并完成准备
- **THEN** 服务端开始统一节拍循环
- **THEN** 两端看到相同的玩家编组与初始战场状态

### Requirement: JSON 节拍同步协议
系统 SHALL 基于 JSON 定义可版本化的网络消息协议，至少覆盖房间控制、输入命令、状态快照、事件广播、心跳与重同步消息。

#### Scenario: 客户端提交输入
- **WHEN** 客户端在某个逻辑节拍内产生操控输入
- **THEN** 客户端将输入封装为带节拍号和序号的 JSON 消息上传
- **THEN** 服务端只按节拍顺序消费该输入

### Requirement: 模型层按节拍推进
系统 SHALL 将模型层核心更新改造为可在固定逻辑节拍下重复执行的纯计算流程，保证同一输入序列在服务端得到唯一战局结果。

#### Scenario: 服务端推进战局
- **WHEN** 服务端到达下一个逻辑节拍
- **THEN** 它按固定顺序处理各玩家输入、AI 决策、导弹更新、碰撞判定与战局结算
- **THEN** 产出带版本号的权威状态快照

### Requirement: 客户端状态纠偏与重同步
系统 SHALL 在检测到客户端本地状态与服务端快照偏差超阈值时，执行状态纠偏或全量重同步，而不是静默继续运行错误状态。

#### Scenario: 网络抖动导致状态偏差
- **WHEN** 客户端因延迟、乱序或短时丢包造成本地预测状态偏离权威快照
- **THEN** 客户端执行平滑纠偏或请求全量重同步
- **THEN** 在限定恢复时间内回到与服务端一致的战局版本

### Requirement: 弱网场景下的联机稳定性
系统 SHALL 在可控的网络波动场景下维持对战可用性，至少提供心跳超时检测、短时重连提示与状态恢复机制。

#### Scenario: 短时网络抖动
- **WHEN** 某客户端出现短时高延迟或瞬时断连
- **THEN** 本地界面明确显示同步状态
- **THEN** 服务端保留该玩家短暂重连窗口
- **THEN** 重连成功后客户端恢复到最新权威状态

## MODIFIED Requirements
### Requirement: 控制层驱动显示层
系统仍 SHALL 保持显示层只从控制层获取快照数据，不直接访问模型对象；但控制层现在必须同时协调本地渲染循环与网络会话状态，将权威快照转换为可渲染视图数据。

### Requirement: 网络接口预留
原有 `INetworkProtocol` 不再只是空接口预留，系统 SHALL 提供可运行的 JSON 协议实现，并补充消息类型、版本字段、序列号和错误处理约束。

## REMOVED Requirements
### Requirement: 单机模式下完全本地裁决
**Reason**: 网络对战需要统一的权威裁决来源，继续由客户端各自本地结算会导致多端状态分叉。
**Migration**: 将命中、击毁、战局推进迁移到服务端节拍循环，客户端仅保留输入采集、预测显示与快照消费能力。
